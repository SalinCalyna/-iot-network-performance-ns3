    AODV

    Reactive routing

    Discovers routes on demand via RREQ/RREP flooding; only pays discovery cost when a route is actually needed.

    OLSR

    Proactive routing

    Maintains routes continuously via periodic Hello/TC messages, regardless of whether traffic needs them.

    Static

    Static routing

    Fixed BFS shortest-hop routes computed once from an assumed 90 m disk connectivity model; never adapts at runtime.

    1. IoT sensors generate data (temperature, air quality, parking occupancy, security events, and more).
    2. Data is transmitted through the wireless mesh.
    3. Multi-hop nodes forward packets toward the gateway.
    4. The gateway collects the data.
    5. The server processes the data.
    6. Network performance can be evaluated using PDR, Throughput, End-to-End Delay, and Packet Loss.

    The V2.7.1 analysis identified a possible difference in how FlowMonitor counts transmitted packets for AODV, due to routing retry/requeue behaviour in ns-3's AODV implementation. Therefore, AODV PDR should not yet be treated as a final, confirmed comparison against OLSR/Static.

      V4 — Sigmoid-Based Adaptive Routing PROPOSED — NOT YET IMPLEMENTED

      Research direction inspired by Sigmoid-Enhanced OSPF (SE-OSPF)

      V4 is a proposed extension of the advisor's SE-OSPF research (Thaenchaikun & Kanjanasit, "Performance Analysis of Sigmoid-Enhanced OSPF for Risk-Aware Adaptive Routing in Secure Networks", Network (MDPI), vol. 6, no. 3, art. 52, 2026 — read the paper ↗) to the wireless IoT mesh environment used throughout this project. No V4 code has been written, no V4 simulation has been run, and no V4 performance numbers exist. Everything on this page is a design proposal awaiting advisor review — see Current Status below.

      1. Research Basis FROM THE PAPER

      The advisor's SE-OSPF pipeline, as described in the paper:

      Structural Risk (node degree / max degree)
      ↓
      Normalized Risk R_ij
      ↓
      Sigmoid Function
      ↓
      Routing Cost
      ↓
      Shortest Path (Dijkstra / OSPF)

      The paper's sigmoid formulation:

      f_r = 1 / (1 + exp(-k(x - x0)))

      Cost_ij = C_min + (C_max - C_min) × f_r

      • x = normalized structural risk (the paper states x = R_ij directly)
      • x0 = sigmoid midpoint (paper tests 30, 50, 70)
      • k = sigmoid steepness (paper tests 0.1–0.5)
      • C_min, C_max = routing cost bounds

      These equations are the advisor's published research basis and are NOT yet implemented in V4. They are reproduced here for reference only.

      2. How V4 Extends the Paper PROPOSED EXTENSION

      Advisor's SE-OSPFOur V4 (proposed)
      OSPF (wired, link-state)AODV / OLSR / Static (wireless ad-hoc mesh)
      Barabási–Albert scale-free topologyExisting V3 topology-generation method (V2's uniform-random placement), unchanged
      Topology-based structural risk (only input)Structural risk and measured link utilization (two inputs)
      One sigmoid functionTwo independent sigmoid functions (risk, load)
      Single-input cost, DijkstraWeighted adaptive cost combining both sigmoids, same edge-cost-minimization principle
      Evaluated against Standard/Linear OSPFEvaluated against AODV / OLSR / Static (this project's existing baselines)

      This is a proposed extension, not an existing result. See docs/v3-experiment-framework.md and the V4 design-analysis notes for the full reasoning behind each adaptation.

      3. Proposed V4 Model PENDING ADVISOR APPROVAL

      Node Degree
      ↓
      Structural Risk R_ij
      ↓
      Sigmoid Risk Function
      ↓
      Risk Cost
      Link Utilization
      ↓
      Load Score L_ij
      ↓
      Sigmoid Load Function
      ↓
      Load Cost
      Risk Cost + Load Cost
      ↓
      Weighted Adaptive Cost
      ↓
      Route Selection

      Proposed V4 mathematical model — pending advisor approval, not the final model:

      • RiskScore_ij = normalized structural risk (same form as the paper's R_ij)
      • LoadScore_ij = measured link utilization (already in V3-ext's own metric set)
      • SigmoidRisk_ij = 1 / (1 + exp(-k_R(R_ij - x0_R)))
      • SigmoidLoad_ij = 1 / (1 + exp(-k_L(L_ij - x0_L)))

      AdaptiveCost_ij = w_R × SigmoidRisk_ij + w_L × SigmoidLoad_ij, with w_R + w_L = 1

      Lower AdaptiveCost_ij would be preferred (same minimization direction as the paper's Dijkstra-based selection) — if and when this is implemented.

      6. V4 Experiment Plan (Planned — Not Run)

      1. Stage 1 — Parameter validation / sensitivity study: vary k_R, k_L, w_R, w_L on a small validation subset.
      2. Stage 2: select a justified parameter configuration from Stage 1.
      3. Stage 3 — Matched-condition comparison: AODV, OLSR, Static, V4-Sigmoid, all under identical conditions.
      4. Stage 4 — Evaluate: PDR, Throughput, Delay, Jitter, Packet Loss, Routing Overhead, Hop Count, Path Changes, Average Link Utilization, Maximum Link Utilization.
      5. Stage 5: run the final experiment using Seeds 20–30.

      No numerical V4 results are shown above or anywhere on this page, because none exist yet.

      V4 will be compared under identical experimental conditions. Kept unchanged from V3: Area Size (250 × 250 m), Transmission Range (90 m), node placement/topology-generation method, traffic conditions, mobility conditions, Seeds (20–30), and simulation duration. This prevents any apparent improvement from being caused by a changed network environment rather than the routing method itself.
