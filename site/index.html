Network Utilization / Bottleneck Evidence
Mechanism Evidence✓ Measured (proxy)

Maximum Link Utilization vs. Network Size

busiest single link, % of nominal PHY rate

Maximum Link Utilization is distinct from Gateway Airtime (see Bottleneck Analysis, below) — MLU is a per-neighbour-pair delivered-load ratio against nominal PHY rate, computed for the single busiest link in each topology; Gateway Airtime measures the sensor-facing gateway's own channel-busy fraction specifically. MLU excludes retries, backoff, ACKs, headers, and other nodes' airtime, and per-link load spreads out as N grows — so a low MLU value is not evidence of an uncongested channel; taken at face value it would understate congestion. Treat it as a relative hot-link indicator, not a measured airtime fraction.

A · Existing Evidence△ LIMITED COVERAGE — V4 Activation Screen

Does adaptive routing solve the problem? — what has already been measured

Sigmoid-based adaptive routing (V4) vs. Static, across 6 activation-screen configurations (N=50, medium traffic, 11 seeds each). This is completed, frozen research — presented here as the evidence that motivates investigating the routing metric further, not as a validated solution.

Key FindingRouting activation ≠ performance improvement — the strongest-activation V4 configuration re-routes 100% of seeds but does not produce a statistically credible PDR gain.
Research result
Routing activation ≠ performance improvement. The adaptive routing mechanism changed routing behaviour under selected conditions, but did not produce credible overall performance improvement relative to Static. This is treated as a valid scientific negative result, not a failed implementation.
ConfigurationRoute-tree change vs. StaticActivated?PDR (V4)PDR (Static)
The strongest-activation configuration (100% of seeds re-routed, mean hop count +27.9%) produced a PDR change of only +3.5%, not statistically credible (sign-test p=1.0), while delay worsened 21.6% and link utilisation worsened 42.8%.
B · V3 Research Direction — Sigmoid Routing Metric

Why an adaptive routing metric?

Current routing decisions may not sufficiently account for changing network conditions. Therefore, the next research step is to investigate whether a continuous routing metric can translate network conditions into an adaptive routing decision.

Key Findings

Research Conclusion

  1. 01Network scale and traffic load are major determinants of IoT network performance.
  2. 02Performance degradation is associated with increasing gateway / first-hop congestion and queue pressure.
  3. 03Traffic reduction can substantially improve PDR under high-density conditions.
  4. 04Routing protocol behavior must be evaluated under controlled network conditions rather than assuming one protocol is universally superior.
  5. 05Adaptive Sigmoid routing remains future research and requires controlled experiments and statistical validation.

The study identifies gateway and first-hop congestion as the dominant measurable bottleneck under near-saturated conditions and demonstrates that reducing offered traffic rate can effectively mitigate this bottleneck and improve PDR in OLSR networks at high node densities. However, the effectiveness of the intervention is protocol- and load-dependent, and a portion of packet loss remains unattributed by the current instrumentation.

Limitations

AODV
FlowMonitor PacketsSent-denominator artifact affects interpretation of PDR/PacketLoss — read as indicative, not exact.
OLSR
RoutingOverheadPackets = 0 is a metric-coverage limitation, not proof of zero control traffic.
Static
Some residual packet loss remains unattributed (64.65%–99.57% at Static/N=50, typically ≥92%).
