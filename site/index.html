    Protocols ACTUAL DATA

    AODV

    Reactive routing

    Discovers routes on demand via RREQ/RREP flooding; only pays discovery cost when a route is actually needed.

    OLSR

    Proactive routing

    Maintains routes continuously via periodic Hello/TC messages, regardless of whether traffic needs them.

    Static

    Static routing

    Fixed BFS shortest-hop routes computed once from an assumed 90 m disk connectivity model; never adapts at runtime.

    From Simulation to Real-World Application

    1. IoT sensors generate data (temperature, air quality, parking occupancy, security events, and more).
    2. Data is transmitted through the wireless mesh.
    3. Multi-hop nodes forward packets toward the gateway.
    4. The gateway collects the data.
    5. The server processes the data.
    6. Network performance can be evaluated using PDR, Throughput, End-to-End Delay, and Packet Loss.

    Experimental Validity

    V2.7 Limitation: AODV packet-count accounting requires further validation before making definitive cross-protocol PDR comparisons.

    ✓ Confirmed

    • Same topology seeds (1–5) are used across AODV, OLSR and Static at each network size
    • 5 independent trials per scenario
    • 12 scenarios evaluated (3 protocols × 4 network sizes)
    • No arithmetic anomalies found (PDR>100%, negative values, rx>tx, etc.)
    • Throughput and delay comparisons across protocols and network sizes

    ⚠ Under investigation

    PDR comparison requires validation

    The V2.7.1 analysis identified a possible difference in how FlowMonitor counts transmitted packets for AODV, due to routing retry/requeue behaviour in ns-3's AODV implementation. AODV's PacketsSent count was observed to scale with topology/network size in a way OLSR's and Static's counts do not. Therefore, AODV PDR should not yet be treated as a final, confirmed comparison against OLSR/Static.

    • AODV PDR comparison against OLSR/Static N/A
    • AODV's PacketsSent denominator
    • Exact packet-loss causes (MAC contention vs. PHY loss vs. queue drops vs. routing failure — not instrumented) N/A
    • Packet Loss for AODV specifically inherits the PacketsSent caveat (Loss = Sent − Received)

    The metric

    S(x) = 1 / (1 + exp(-k * (x - x0))) is implemented in scratch/iot-network-v3.cc as a 4th routing mode (Dijkstra over sigmoid-weighted edges), applied to two geometrically-justified proxies:

      Full derivation and the k-value near-linear-regime analysis: docs/sigmoid-metric.md, docs/methodology.md, docs/experiment-design.md.

      Scope: only a single 4-run smoke test has been executed (1 seed, medium traffic, 15 nodes, one run per protocol) to confirm the sigmoid mode compiles, runs, and produces sane output. The full experiment matrix has not been run. With n=1 per protocol these 4 rows carry no variance estimate and no statistical basis for claiming sigmoid routing outperforms (or underperforms) AODV/OLSR/Static — FUTURE WORK.
